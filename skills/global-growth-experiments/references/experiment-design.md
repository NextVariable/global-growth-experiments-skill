# 从业务决定设计实验

## 选择值得做的试验

先写“如果知道什么，我们会改变哪项投入”。把想法写成“对谁，改变哪一步，通过什么机制，预计改变哪个行为”。例如：为已连接数据源却没有完成首次核对的团队提供带样例的首用流程，减少空白设置的理解成本。只说“改首页提高增长”不够。

优先检验当前决策最脆弱而且可以被改变的假设。比较影响、已有证据、执行/服务成本、结果延迟、可逆性和失败代价；评分只能表达显式假设，不能用小数总分制造客观排名。保留暂不测试的理由，避免一次安排过多互相污染的改动。

## 选对证据方式

| 当前未知 | 合适的第一步 | 能与不能说明什么 |
|---|---|---|
| 用户看不懂下一步 | 观察目标用户完成真实任务 | 能定位理解/操作障碍，不能估计全体提升幅度 |
| 客户是否愿意投入 | 有明确条件的试点、预约、真实付款或资源承诺 | 分清意向与行为；不能把免费报名当付费需求 |
| 足够流量下两个版本效果 | 随机对照，预先定义终点 | 有效分流和测量是因果解释前提 |
| 小群体、长销售周期 | 限定队列试点并记录先前状态/替代解释 | 可形成继续投入条件，不能假装有统计功效 |
| 渠道贡献难识别 | 核对一方事件，必要时设计留出/地区或时间试验 | 地区、时段差异与外溢须建模；不能把任意地区对比当随机试验 |

没有流量时不要先堆样本量公式。用可获得样本排除明显障碍，或等待足够事件；无法可靠检验小幅变化，就说明当前问题不可检验，不偷偷把目标改成容易显著的指标。

## 随机试验需要定义的事

先确定用户、账户、组织或其他分配单位，稳定分流，同一单位保持版本；分析单位与随机化一致。记录符合条件的人群、纳入/排除规则、分配比例、暴露条件、重复访问和跨设备处理，说明并行实验与互相影响。

区分三个数：**业务上值得实施的最小变化**、为计划样本量设置的**可检出变化**、最后观测到的**估计变化**。绝对百分点和相对百分比不可混写；基线为零时相对变化没有定义。

样本量计划须有基线及出处、方差/分布、可检出变化、分配比例、显著性/功效或其他明确推断框架。使用计算工具并保存参数；独立二元模型的计划不能直接套组织聚类、金额或长尾时长。不提供脱离输入的“通用所需样本”。

按可入组单位、分配比例、转化延迟和业务周期估计时长。样本量达到但结果尚未成熟时仍须等待。周期不是一律七天或二十八天；无法在预算内获得可靠结果时调整问题或方法。

## 事先写清判定

选择一个主要业务结果，并写必要护栏和机制指标。护栏涵盖与该改动有关的退款、退订、错误率、服务成本、延迟和可交付性，不是越多越好。没有历史基线时先测量，不能自行设“健康值”。

事先约定：什么证据足以扩大、什么损害触发停止、什么结果只能暂不判断、什么时点检查。固定终点与序贯方法择一并遵守；多组、多主指标或多次决策要有对应控制，事后分群标为探索。

执行日常安全检查不等于每天做一次胜负检验。达到预先授权的安全停止条件就按约定停，不因等待统计显著而继续伤害客户；没有操作授权时立即升级并给明确停用步骤。发生故障或方法改变，保留旧轮次，注明新轮次，不能合并成无中断成功实验。
