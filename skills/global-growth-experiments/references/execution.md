# 执行与恢复

## 让实验能实际运行

确认本轮产物及其版本、投放/上线位置、符合条件的对象、执行人或可用工具、资源上限、观察时间和停止方式。内容制作可交第二部分；渠道操作交第三部分；客户试点/激活/续费操作交第四部分。若没有这些 Skill，也能直接提供清楚的操作包，不能把安装它们作为完成任务的前提。

一个操作包应足以让执行者完成：准确对象与位置、使用哪份资产、分配或触发方式、应看到的状态、事件记录、遇错处理和回退方法。给用户的工作说明用可执行语言，不把内部评估规则当作客户内容。

在已授权范围内先完成可逆准备、草稿、预览和核对。对外发送、发布、支出或改动线上配置需要对应明确授权；已有授权可复用，不反复要求确认。不因 Skill 名称包含“执行”获得无限操作权。定期监控与自动任务仅在用户要求时建立。

## 上线前与上线后

用一次完整动作验证入口、权限、资产、事件和回退，避免只看到成功页面就认定数据链通了。试验分流的演练和真实用户暴露要区分；不得编造“测试用户已转化”。

执行后回读目标系统，记录实际对象、版本、时间和可核验回执。动作完成、受众收到、受众行动和业务有效是不同状态。多个渠道分批执行，报告成功、失败、状态未知和未尝试；不能把创建草稿写成全部上线。

超时或断线时先查目标系统是否已经完成，使用已有对象 ID、活动标识或其他去重线索核对；没有证据不要盲目重复发送、扣款、建活动。无可靠回读则标状态未知并说明如何确认。

## 运行变化

预算、人力、错误率或其他约定护栏触线时执行授权内的暂停/回退，并保存故障时间、受影响范围、样本和原因。没有控制权则立即标出应停止的具体动作及负责人，不把建议暂停写成已经停用。

价格、产品能力、素材或埋点定义中途改变时，不覆盖旧版本。判断旧试验是否还能回答原假设；受影响的新暴露单独标记，必要时结束旧轮次并重新设计。不能把旧价和新价转化直接混算为同一版本效果。

如果客户反馈暴露产品缺陷，给产品团队最小复现步骤、影响行为/人群、当前替代办法及验证条件，不虚构排期和修复承诺。修好后核验原失败路径，再决定是否恢复试验。
